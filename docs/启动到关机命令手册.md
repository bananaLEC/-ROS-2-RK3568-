## 0. 开机前的硬件检查

| 检查项 | 怎么看 |
|---|---|
| 电池电压 | 网页状态 > 11.0 V；低于 10.5 V 先充电 |
| 雷达 | 上电后**必须转起来**，不转 = 没供电 |
| 相机 | USB3.0 口（Astra Pro 占一个 CH340 口的话要错开） |
| CAN 接线 | 40Pin pin1=3V3, pin3=CAN_RX, pin5=CAN_TX, pin6=GND |
| 网线 | 可选，`end0` 千兆口比 WiFi 稳 |
| 散热 | 编译前摸一下，烫手先停 |

> ⚠️ 上电顺序建议：**先接线 → 再上电**。热插拔 USB 相机/雷达容易让 udev 名字乱。

## 1. 上电与串口调试

### 1.1 正常上电

给 12V（或电池）上电，观察指示灯：

| 指示灯 | 正常状态 |
|---|---|
| 绿色（Power） | 常亮 |
| 蓝色（Work） | **闪烁** |

> 蓝灯灭、绿灯常亮 = 系统运行异常 → 先短按一次 `POWER` 键重启；还不行走第 13 章。

### 1.2 接调试串口（出问题时才需要）

**接线**（40Pin 排针，USB-TTL 模块）：

| USB-TTL 线 | 小车引脚 |
|---|---|
| TX（绿） | Pin 35 (DEBUG_UART2_RX) |
| RX（白） | Pin 37 (DEBUG_UART2_TX) |
| GND（黑） | Pin 39 (GND) |
| VCC（红） | **不接** |

**串口参数**：`1500000 8N1`，无流控（瑞芯微是 1.5M，不是 115200）。

**上位机抓日志**：
```bash
sudo chmod a+rw /dev/ttyUSB0
python3 "/home/banana/文档/deepseek-harness/default-workspace/capture_serial.py" /dev/ttyUSB0 1500000
# 然后按板子 RESET，日志会同时打印并存到 logs/serial_capture_*.log
```

**进 U-Boot 命令行**（救砖用）：
```bash
python3 "/home/banana/文档/deepseek-harness/default-workspace/uboot_catch.py" 240 /tmp/uboot.log
# 看到 => 就进去了
```

## 2. 网络与连接

### 2.1 上位机检查

```bash
ip -br addr show wlo1          # 应该是 192.168.3.x
ip route | head -3             # 默认网关 192.168.3.1
ping -c 3 192.168.3.100        # 测小车
nc -z -w 3 192.168.3.100 22 && echo "SSH 通"
```

> 如果 `ping` 报 `socket: 不允许的操作`（容器/受限环境），用 `nc -z` 或直接 ssh 测。

### 2.2 找到小车（不知道 IP 时）

```bash
# 扫全网段 22 端口
seq 1 254 | xargs -P 128 -I{} bash -c 'nc -z -w 1 192.168.3.{} 22 2>/dev/null && echo "192.168.3.{}"'

# 或看 ARP 表
ip neigh show | grep -v FAILED

# 或登录路由器后台看在线设备
```

### 2.3 SSH 连接

```bash
ssh kickpi-robot                # 已配好 ~/.ssh/config 的别名
ssh kickpi@192.168.3.100        # 等价写法
```

**VSCode Remote-SSH**：
1. `Ctrl+Shift+P` → `Remote-SSH: Connect to Host...`
2. 选 `kickpi-robot`
3. 首次会在小车上装 vscode-server（约 100MB，几分钟）
4. 连上后「文件 → 打开文件夹」→ `/home/kickpi`

### 2.4 上位机 ROS 环境（连小车用）

```bash
source ~/robot_ws_env.sh
# 输出 ✅ Zenoh 已中继到小车 192.168.3.100:7447 就是连上了
```

它做了三件事：
1. `source /opt/ros/jazzy/setup.bash` + 本机 `~/ros2_ws`（URDF 包）
2. 设置 `ROS_DOMAIN_ID=42`、`RMW_IMPLEMENTATION=rmw_zenoh_cpp`
3. 确保本机 Zenoh 中继路由器在跑（连小车 `tcp/192.168.3.100:7447`）

**中继服务管理**：
```bash
systemctl --user status rz-zenoh-relay
systemctl --user restart rz-zenoh-relay
ss -tn | grep 192.168.3.100:7447        # 应有 ESTAB 连接
```

## 3. 启动 ROS 全栈

### 3.1 一键启动（推荐）

```bash
ssh kickpi-robot 'BASE_MODE=can bash ~/robot_start.sh'
```

或者从网页/上位机触发（详见第 4 章 `/api/start`）。

**它会依次拉起**：
1. 等待设备就绪（`/dev/rplidar`、`/dev/jy901`）
2. 确认 `can0` UP（systemd `can0-up.service`）
3. 底盘 launch（`use_serial:=false`，跳过串口节点）
4. **CAN 桥接节点** `can_chassis_bridge.py`（0x181 下行 / 0x101-0x103 上行）
5. JY901 IMU（100 Hz）
6. RPLIDAR A1
7. slam_toolbox + 激活 lifecycle
8. foxglove_bridge（TCP 8765）
9. 自检

### 3.2 手动逐条启动（学习用）

```bash
ssh kickpi-robot
source ~/rosenv.sh                    # 关键：环境（含 RMW、domain、jy901 包路径）
```

**① CAN 接口**
```bash
sudo ip link set can0 down
sudo ip link set can0 up type can bitrate 1000000
ip -br link show can0                 # 期望 UP
candump can0                          # 应看到 101/102/103 帧
```

**② 底盘 CAN 桥接**
```bash
setsid nohup python3 /home/kickpi/can/can_chassis_bridge.py \
  --ros-args -p channel:=can0 -p odom_topic:=/odom \
  > /tmp/can_bridge.log 2>&1 < /dev/null &
tail -3 /tmp/can_bridge.log           # 期望 "CAN 桥接已启动"
```

**③ IMU**
```bash
setsid nohup ros2 run jy901_imu jy901_node > /tmp/imu.log 2>&1 < /dev/null &
tail -3 /tmp/imu.log                  # 期望 "gyro bias: ..."（启动零偏校准）
```

**④ 雷达**
```bash
setsid nohup ros2 launch rplidar_ros rplidar_a1_launch.py \
  serial_port:=/dev/rplidar > /tmp/lidar.log 2>&1 < /dev/null &
tail -3 /tmp/lidar.log                # 期望 "current scan mode: Sensitivity"
```

**⑤ 底盘 URDF / 静态 TF / EKF**
```bash
setsid nohup ros2 launch turn_on_wheeltec_robot turn_on_wheeltec_robot.launch.py \
  car_mode:=mini_mec use_serial:=false > /tmp/chassis.log 2>&1 < /dev/null &
```

**⑥ SLAM**
```bash
setsid nohup ros2 run slam_toolbox async_slam_toolbox_node --ros-args \
  --params-file /home/kickpi/ros2_ws/install/wheeltec_slam_toolbox/share/wheeltec_slam_toolbox/config/mapper_params_online_async.yaml \
  > /tmp/slam.log 2>&1 < /dev/null &
sleep 5
ros2 lifecycle set /slam_toolbox configure
ros2 lifecycle set /slam_toolbox activate
```

**⑦ Foxglove 可视化桥**（可选）
```bash
setsid nohup ros2 run foxglove_bridge foxglove_bridge --ros-args -p port:=8765 \
  > /tmp/foxglove.log 2>&1 < /dev/null &
```

### 3.3 停止全栈

```bash
ssh kickpi-robot 'bash ~/robot_stop.sh'
```

**手动版**：
```bash
pkill -f "turn_on_wheeltec_robot.launch"
pkill -f "can_chassis_bridge"
pkill -f "rplidar_node"
pkill -f "jy901_node"
pkill -f "slam_toolbox"
```

### 5.3 RViz 里有什么

## 6. 建图操作流程

### 6.1 操作要点

| 要点 | 说明 |
|---|---|
| **慢** | 0.1–0.2 m/s，快了匹配失败地图会糊 |
| **转向前先停** | 边走边急转会产生扇形拖影 |
| **走闭合回路** | 触发回环优化，墙会立刻变直 |
| **每个房间都进去** | 门框两侧都要扫到 |
| **避开玻璃/白墙/强光** | 激光打不到会丢定位 |
| **地图上的小点不要删** | 那是凳子腿/桌腿，**真实障碍** |

### 6.2 已调过的 SLAM 参数

文件：`~/ros2_ws/src/wheeltec_slam_toolbox/config/mapper_params_online_async.yaml`

| 参数 | 原值 | 现在 | 作用 |
|---|---|---|---|
| `minimum_travel_distance` | 0.0 | 0.10 | 减少节点密度 |
| `link_match_minimum_response_fine` | 0.1 | 0.45 | 拒绝低质量匹配，抑制拖影 |

> 若出现"定位丢失 / 地图断裂"，把第二个改回 `0.1`。

### 6.3 直道交叉处偏移（待解决）

**现象**：两条直道交叉处出现偏移，最长主直道在建好的地图里整体偏了。

**可能原因**（按概率）：
1. **走太快** → 里程计累积误差 → 先降到 0.1 m/s 复测；
2. **转向前没停** → 麦轮打滑，yaw 累积误差大；
3. **IMU 零偏** → 启动时车在动，零偏校准没通过（看日志 `std < 0.05` 才算有效）；
4. **雷达安装偏角** → static TF 里 yaw=π 是否准确；
5. **`link_match_minimum_response_fine` 0.45 太严** → 拒绝了一些正确匹配。

**排查建议**：
```bash
# 1. 静止 30 秒看 IMU 零偏是否稳定
source ~/rosenv.sh
ros2 topic echo /imu/data_raw --field angular_velocity

# 2. 原地转 360° 再转回来，看 yaw 是否回到原点
ros2 topic echo /odom_combined --field pose.pose.orientation

# 3. 直推 1 米，看 /odom 位移是否接近 1 米（麦轮标定）
```

## 8. 导航 Nav2

### 8.1 前提

- 已有保存好的地图
- 全栈已启动（**不要**启动 slam_toolbox，Nav2 用 map_server + AMCL）

### 8.2 启动

```bash
# 1. 启动全栈（不含 SLAM 时，把 robot_start.sh 里 slam 那段注释掉，或直接用下面的手动方式）
ssh kickpi-robot
source ~/rosenv.sh

# 2. 启动 Nav2（用自己建的地图）
ros2 launch wheeltec_robot_nav2 wheeltec_nav2.launch.py \
  car_mode:=mini_mec \
  map:=/home/kickpi/maps/my_map_20261109.yaml
```

### 8.3 关键参数

文件：`~/ros2_ws/src/wheeltec_robot_nav2/param/wheeltec_params/param_mini_mec.yaml`

| 参数 | 当前值 | 说明 |
|---|---|---|
| `inflation_radius`（局部） | 0.15 | 膨胀半径 |
| `inflation_radius`（全局） | 0.2 | |
| `cost_scaling_factor` | 5.0 / 3.0 / 10.0 | 成本衰减 |
| `xy_goal_tolerance` | 0.25 | 到点 XY 容差 |
| `yaw_goal_tolerance` | 0.25 | 到点朝向容差 |
| `odom_topic` | `/odom_combined` | 与 EKF 输出一致 |
| `scan_topic` | `scan` | |
| `robot_model_type` | `DifferentialMotionModel` | 麦轮用差速近似 |

> ⚠️ 凳子间距 0.5–0.6 m 时，`inflation_radius` 设 0.3 会**把路堵死**。从 0.15 开始试。

### 8.4 调试顺序

1. **静态验证**：`/map` 有数据？RViz 能看到地图？
2. **AMCL 定位**：RViz 里用 `2D Pose Estimate` 给初始位姿，看粒子云是否收敛
3. **单点导航**：给近处目标，看路径是否合理
4. **逐步加距离**
5. **最后调速度上限和膨胀半径**

### 8.5 命令行发目标

```bash
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: map}, pose: {position: {x: 1.0, y: 0.5}, \
   orientation: {w: 1.0}}}}"
```

## 9A. IMU 标定与旋转验证（重要）

> 2026-11-14 新增。EKF 的航向完全依赖 IMU 陀螺积分，
> 所以**每次上电后先标定、必要时做一次旋转验证**。

### 9A.1 启动前零偏标定（已自动化）

`robot_start.sh` 启动 IMU 之前会自动执行，输出形如：

```
启动前 IMU 零偏标定（请保持小车静止 3 秒）...
  ✓ 零偏 -0.0073 -0.0051 +0.0152 rad/s  (std 0.0080, 302 帧)
```

**此时必须让小车静止**（轮子不动、不要扶着晃）。
判据：三轴 std < 0.05 rad/s，不满足会自动重试 3 次。

手动执行 / 查看：
```bash
ssh kickpi-robot
python3 ~/imu_precalib.py            # 手动标定
python3 ~/imu_precalib.py --show     # 查看上次标定结果
```

结果保存在 `~/jy901_bias.json`，`jy901_node` 启动时直接加载。
删除该文件则退回节点内的在线校准（前 200 帧需静止）。

### 9A.2 旋转验证：轮式里程计 vs 陀螺 vs EKF

**⚠️ 手转无效**：电机使能时轮子被抱死，编码器读不到，测出来一定是错的。
必须**电机驱动**。

```bash
ssh kickpi-robot
source ~/rosenv.sh
python3 ~/rotate_test.py        # 左转 90° → 停 → 右转 90° 回原位，约 20 秒
```

正常输出示例：
```
方向       陀螺      轮式odom      EKF
左转     +170.4°    +160.7°    +173.7°
右转     -170.x°    -160.x°    -173.x°
```

判读标准：

| 现象 | 含义 | 处理 |
|---|---|---|
| EKF ≈ 陀螺（差 < 5°） | 正常 | 无需处理 |
| EKF 明显大于陀螺（>10°） | `queue_size` 太小 / 滤波频率过高 | 把 `odom0_queue_size`、`imu0_queue_size` 调回 5 |
| 轮式 odom 与陀螺差 > 15% | 轮径/轮距标定或打滑严重 | 检查地面、降速 |
| EKF 偏向轮式值 | IMU 权重不足 | 检查 `imu0_config` 的 yaw_vel 是否 true |

### 9A.3 记录时间序列（深入排查）

```bash
python3 ~/yaw_trace.py       # 转一次，输出 ~/yaw_trace.csv
```

CSV 列：`t_rel, stamp, wz, integ_deg, odom_deg, ekf_deg`
用于判断"误差是逐渐累积（尺度问题）还是停车后继续增长（积分失真）"。

### 9A.4 EKF 调参铁律

1. **`queue_size` 不能低于 `传感器频率 ÷ 滤波频率`**
   - 100Hz IMU + 10Hz 滤波 → 每周期 10 条消息，`imu0_queue_size` 至少 5，给 2 必然失真
   - 提高 `frequency` 时必须同步加大 `queue_size`
2. **不要随意关闭传感器**：先用协方差降权，确认信号真的无效再关
3. **协方差要反映真实可信度**，不要一律 `1e-3`
4. 改完参数**必须用 `rotate_test.py` 验证**，不要直接去建图

## 13. 异常处理

### 13.1 SSH 连不上

| 现象 | 排查 |
|---|---|
| `No route to host` | 小车没开机 / 没连 WiFi / IP 变了 → 扫网段 |
| `Connection refused` | sshd 没起来 → 接 HDMI 或串口看 |
| `Permission denied (publickey)` | 公钥丢了 → 本地终端加公钥 |

```bash
# 扫网段找它
seq 1 254 | xargs -P 128 -I{} bash -c 'nc -z -w 1 192.168.3.{} 22 2>/dev/null && echo found:192.168.3.{}'
```

### 13.2 蓝灯灭、系统起不来

1. 先短按 `POWER` 键重启一次；
2. 还不行 → 接调试串口看日志（第 1.2 节）；
3. 判断依据：

| 串口日志 | 问题 | 处理 |
|---|---|---|
| 有 `U-Boot SPL` + `Invalid DTB hash` | boot 分区问题 | U-Boot 恢复（13.3） |
| `EXT4-fs error` / `Failed to mount /` | rootfs 损坏 | fsck 或重刷 |
| `Kernel panic` | 内核崩 | 看 panic 前几行 |
| **完全无输出**（换 TX/RX、换 115200 也不行） | 没进 bootloader | Maskrom 重刷 |

### 13.3 boot 分区救砖（U-Boot UMS 流程）

```bash
# ① 上位机：抓串口 + 发 Ctrl-C
sudo chmod a+rw /dev/ttyUSB0
python3 ".../uboot_catch.py" 240 /tmp/uboot.log
# 按板子 RESET，看到 => 即可

# ② U-Boot 里（用 uboot_send.py 或手动在串口终端敲）
ums 0 mmc 0

# ③ 上位机：找到 eMMC 挂成的 U 盘
lsblk                     # 找 29.1G 的 UMS disk，假设是 /dev/sda

# ④ 写回原版 boot
sudo dd if=~/robot_backup_20261107/home/kickpi/can/boot_emmc_orig.img \
        of=/dev/sda3 bs=1M conv=fsync status=progress
sync
sudo md5sum /dev/sda3     # 期望 d713e34840e35ce747964aec4ee9d80c

# ⑤ U-Boot 里退出发 reset
# Ctrl-C 退出 ums，然后：
reset
```

> 目标分区 `/dev/sda3`：PARTLABEL=`boot`，64MB。**千万不要写成 `/dev/sda`**（会毁分区表）。

### 13.4 网页显示"运行中"但车不动

1. 看 `/api/status` 的 `odom_hz` 是否 20；
2. `candump can0` 看底盘有没有回帧；
3. 检查 `~/rmw_mode` 是不是 `zenoh`（我们试过 fastdds，已回退）；
4. 网页进程是否被旧实例占端口（第 5.2 节）。

### 13.5 服务莫名被停

```bash

sudo journalctl -u <服务名> -n 30 --no-pager
# 常见原因：端口被占用、依赖服务在重启
```

1. `use_composition:=false` 必须写 **`False`**（launch 里是 Python 表达式，小写 false 会报 name 'false' is not defined）；
2. 代价地图 `width/height` 必须是**整数**（`4.0` 报类型错误）；
3. `nav2_params.yaml` 里**不要**写 `map_server` 段（空的 `yaml_filename` 会覆盖 launch 传的 map）；
4. MPPI：`controller_frequency` 的周期必须 ≤ `model_dt`，否则 controller_server 直接 configure 失败；
5. Zenoh 下 BT 的 `default_server_timeout` 20 ms 太短，改成 **3000 ms**；
6. 反复重启会堆积 ROS 进程吃满内存 → **每次先 `clean_all_ros.sh`**。

### 航点文件格式
```yaml
waypoints:
  - name: "A"
    x: 1.100
    y: 0.170
    yaw: null      # null = 自动取“朝向下一个航点”的方向
```

### 常用命令
