## 1. 概述

### 1.1 这是什么车

一台**四轮麦克纳姆轮（全向）移动机器人**，具备：

- 2D 激光 SLAM 建图（slam_toolbox）
- 基于已有地图的定位（AMCL）
- 点到点自主导航（Nav2：SmacPlanner2D + DWB）
- 多目标点自主巡检（patrol.py）
- 网页控制台（启停、摇杆遥控、摄像头、地图查看、保存地图）
- 笔记本 RViz2 实时可视化（跨机 Zenoh 通信，自动开窗）

### 1.2 系统分层

```
┌─────────────────────────────────────────────────────────┐
│ 应用层   patrol.py / Nav2 NavigateToPose / 网页控制台      │
├─────────────────────────────────────────────────────────┤
│ 算法层   slam_toolbox(建图)  AMCL(定位)  Nav2(规划+控制)   │
│          robot_localization(EKF)                          │
├─────────────────────────────────────────────────────────┤
│ 驱动层   can_chassis_bridge  jy901_node  rplidar_node     │
│          scan_mask  imu_precalib  map_server              │
├─────────────────────────────────────────────────────────┤
│ 通信层   ROS 2 Jazzy + rmw_zenoh_cpp (Domain 42)          │
│          Zenoh Router(7447) ⇄ 笔记本中继                  │
├─────────────────────────────────────────────────────────┤
│ 硬件层   RK3568 / C30D 底盘(STM32+CAN) / RPLIDAR A1       │
│          JY901 IMU / Astra Pro 相机                        │
└─────────────────────────────────────────────────────────┘
```

### 1.3 关键约束（务必牢记）

| 约束 | 说明 |
|---|---|
| **内存只有 4 GB** | 反复重启 ROS 会堆积进程导致内存耗尽、系统 load 飙到几十；**每次启动前先 `clean_all_ros.sh`** |
| **ROS 2 CLI 在 Zenoh 下不稳** | `ros2 topic echo` 可能卡住、`ros2 lifecycle get` 偶尔查不到；用脚本订阅代替 |
| **跨机 Zenoh 发现单向** | 笔记本能收数据但话题列表可能不全；RViz 用**固定话题名**的预设配置 |
| **电池** | 满电约 11.8~12.0 V，**11.1 V 以下**随时可能掉电关机（底盘 STM32 先失电）；建图/巡检前确认电压 |
| **网页「启动/停止」** | 只在建图模式用；定位/导航模式下不要点（会拉 slam 或杀底盘） |

## 2. 硬件架构

### 2.1 计算平台

| 项目 | 参数 |
|---|---|
| 主板 | KICKPI K1 Mini，SoC **RK3568**（4×Cortex-A55） |
| 内存/存储 | 4 GB RAM / eMMC（已从损坏的 TF 卡迁移到 eMMC 启动） |
| 系统 | Ubuntu 24.04 LTS aarch64 |
| 网络 | WiFi，机器人 IP **192.168.3.100**；笔记本电脑 **192.168.3.26** |
| 用户 | `kickpi`（密码见交接说明） |

> 历史：原 TF 卡因错误的 boot/DTB 补丁损坏（`HASH(c): error` + panic），已用 U-Boot `ums` 恢复分区并迁移到 eMMC。当前 boot 补丁为 **CAN 使能 v4**（`boot_emmc_can1_v4.img`），`boot_emmc_orig.img` 为原样备份可救命。

### 2.2 底盘（C30D 麦克纳姆轮）

| 项目 | 参数 |
|---|---|
| 驱动 | 4× 直流减速电机，麦克纳姆轮（辊子 45°） |
| 控制器 | STM32（自带速度闭环，输出编码器速度） |
| 通信 | **CAN 1 Mbps**（`can0`，由 `can0-up.service` 拉起） |
| 运动能力 | vx 前后、vy 左右平移、wz 原地旋转 |
| 控制周期 | 20 Hz（命令帧下发 + 状态帧回传） |

#### CAN 帧定义（桥接节点约定）

| CAN ID | 方向 | 内容 |
|---|---|---|
| `0x181` | 主机 → 底盘 | 命令：`vx(mm/s)`, `vy(mm/s)`, `wz(mrad/s)` 各 int16 大端；周期 20 Hz；0.5 s 无命令自动归零 |
| `0x101` | 底盘 → 主机 | d[0]=状态字节；d[1]=flag_stop；**d[2:4]=vx(mm/s)**；**d[4:6]=vy(mm/s)**；**d[6:8]=wz(mrad/s)** |
| `0x102` | 底盘 → 主机 | 加速度 x,y,z（int16 / 常数） |
| `0x103` | 底盘 → 主机 | 陀螺仪 y,z + 电压（mV） |

> 桥接节点对 `wz` 乘 **yaw_scale = 1.06** 修正轮式偏航标度（实测轮式比陀螺低约 6%）。

### 2.3 电气与电池

- 底盘电池组（实测满电约 11.8 V，约 3S 锂电池）给 STM32 + 电机供电；**RK3568 板载供电独立或经 DC-DC**。
- 应用层电压可从 `/can_chassis_bridge` 日志或 `/battery_voltage` 话题读取（`|电压 11.77 V|`）。
- **低压保护现象**：电压掉到 ~11.1 V 时 STM32 先掉电（底盘无响应），再低则整机断网 → 表现为 SSH/网页突然不通。

### 2.4 传感器

| 传感器 | 接口 | 设备节点 | 数据 |
|---|---|---|---|
| RPLIDAR A1 | USB 串口 | `/dev/rplidar` (udev 固定) | 360° 2D 激光，1080 点/圈，0.333°/点，~16.5–17.5 Hz，量程 0.15–12 m |
| JY901 IMU | UART | `/dev/jy901` | 三轴加速度/角速度，100 Hz，用于 EKF 偏航角速度 |
| Astra Pro 彩色相机 | USB UVC | `/dev/video10` | 640×480 MJPG 直通，15 fps（网页推流） |

### 2.5 安装尺寸（关键 TF 外参）

| 外参 | 值（m / rad） | 来源 |
|---|---|---|
| base_footprint → base_link | (0, 0, 0.074, 0, 0, 0) | `robot_model.yaml` |
| base_footprint → laser | (0.03163, 0.00009, **0.145**, **0, 0, 0**) | 同上（yaw 已由 180° 修正为 0） |
| base_link → laser_link | (0.0316, 0.00009, 0.071, 0, 0, 0) | URDF `laser_joint` |
| base_footprint → gyro_link | (0, 0, 0, 0, 0, 0) | `robot_model.yaml` |
| base_link → camera_link | (0.107, 0, 0.1697) | URDF `camera_joint` |

> ⚠️ **激光 yaw 必须为 0**：曾误配为 π（180°）导致 slam 估的位移与里程计反向、地图反复涂抹。详见第 8.1 节。

## 3. 传感器与设备节点

### 3.1 udev 固定命名

`/etc/udev/rules.d/99-robot.rules` 把 USB 串口固定为 `/dev/rplidar`、`/dev/jy901`，避免 `/dev/ttyUSB*` 顺序变化。

检查：

```bash
ls -l /dev/rplidar /dev/jy901
```

### 3.2 RPLIDAR A1

- 驱动：`rplidar_ros`，launch `rplidar_a1_launch.py serial_port:=/dev/rplidar`
- 原始话题：`/scan`（frame_id = `laser`）
- 特性：`angle_min=-179°`，`angle_max=180°`，`range_max=12.0`（消息字段），实际偶尔出现 14 m 野点（由 slam 的 `max_laser_range: 12.0` 裁掉）

### 3.3 scan_mask（激光遮罩）

- 文件：`~/scan_mask.py`
- 作用：把车体自遮挡的固定扇区从扫描里剔除，发布 `/scan_filtered`
- 扇区参数：`mask_sectors:=155,170,196,206`（单位度，成对 start/end）
- 效果：去掉约 3 个 0.168 m 的自遮挡点；但**仍有少量近点残留**（约 0.18–0.19 m，在 −108° 一带），导航代价地图用 `obstacle_min_range: 0.30` 忽略它们
- **slam 与 AMCL 都使用 `/scan_filtered`**，不要改成 `/scan`

### 3.4 JY901 IMU

- 文件：`~/ros2_ws/src/jy901_imu`（节点 `jy901_node.py`）
- 话题：`/imu/data_raw`（frame_id=`gyro_link`，100 Hz）
- 启动前零偏标定：`~/imu_precalib.py`（静止 3 s 采样，std<0.05 才接受，写入 `~/jy901_bias.json`）
- 注意：**行驶中陀螺噪声较大**（约 ±1–2 °/s 抖动），所以 EKF 只融合它的 **yaw 角速度**，不融合姿态

### 3.5 CAN 底盘桥接

- 文件：`~/can/can_chassis_bridge.py`
- 输入：`/cmd_vel`（来自 Nav2 平滑后的速度或网页摇杆）
- 输出：`/odom`（轮式航位推算，frame `odom` → child `base_footprint`，20 Hz）、`/battery_voltage`
- 航位推算：`x += (vx·cosψ − vy·sinψ)·dt`，`y += (vx·sinψ + vy·cosψ)·dt`，`ψ += wz·dt`
- 协方差：x/y 1e-2，yaw 0.5，yaw 角速度 1e-2
- 关键参数：`yaw_scale=1.06`、`cmd_timeout=0.5`

### 4.3 TF 树

```
map ──(slam_toolbox 或 amcl)──> odom ──(EKF)──> base_footprint
                                                   ├──> base_link ──> {lf,lb,rf,rb}_wheel_link, camera_link, controller_link, laser_link
                                                   ├──> laser        (静态, yaw=0)
                                                   ├──> laser_link
                                                   ├──> gyro_link
                                                   └──> radar
```

- **建图模式**：`map→odom` 由 slam_toolbox 发布
- **定位/导航模式**：`map→odom` 由 AMCL 发布
- `odom→base_footprint` 永远由 EKF 发布（`world_frame=odom`）
- 两个 laser 相关帧：`laser`（静态 TF，扫描用）与 `laser_link`（URDF），两者 yaw 都必须为 0

### 4.4 数据流

**建图**：
```
雷达 → /scan → scan_mask → /scan_filtered ─┐
IMU → /imu/data_raw ──────────────────────┤→ EKF → /odom_combined + TF(odom→base)
CAN 底盘 → /odom ─────────────────────────┘
                                          slam_toolbox → /map + TF(map→odom)
```

**导航**：
```
/scan_filtered + /map + TF → 代价地图 → planner(/plan) → controller(/cmd_vel_nav)
→ velocity_smoother(/cmd_vel) → can_chassis_bridge → CAN 0x181 → 底盘
底盘编码器 → CAN 0x101 → /odom → EKF → TF → (AMCL 修正 map→odom)
```

## 6. 启动与操作流程

### 6.1 三种工作模式

| 模式 | 启动脚本 | 地图 | 适用 |
|---|---|---|---|
| 建图 | `~/robot_start.sh` | 无（slam 实时建） | 首次/环境变化后建图 |
| 定位 | `~/robot_localize.sh` | 静态图 + AMCL | 只定位不导航 |
| 导航 | `~/robot_nav2.sh` | 静态图 + AMCL + Nav2 | 点到点/巡检 |

> 所有脚本都默认 **CAN 模式**（`BASE_MODE=can`）；要临时用串口：`BASE_MODE=serial bash ~/robot_start.sh`。
> 建图/导航启动脚本都会**先杀旧进程**；但建议先手动 `bash ~/clean_all_ros.sh`（防内存堆积）。

### 6.2 建图流程

```bash
# 车上
bash ~/clean_all_ros.sh
bash ~/robot_start.sh            # 或网页控制台点「启动」
# 等输出：✓ slam_toolbox: active / ✓ /map 已就绪 / ✓ 可以开始建图了

# 小车用网页摇杆慢慢开（建议 0.1~0.15 m/s，别长时间直线冲）

# 或网页点「保存地图」
```

**建图要点**：

1. 车速慢、转弯多停一下，让 slam 有时间插入节点；
2. 尽量走**闭环路线**（回到起点附近）触发回环闭合；
3. 别在同一个位置原地转太多圈（会积累伪节点）；
4. 建图后立刻看 `/tmp/slam_monitor.log`，不应有成串 `[MONITOR][JUMP]`。

### 6.3 地图后处理

```bash
# 上位机（工作目录下）
python3 map_clean.py maps/map_xxx.pgm maps/map_xxx_clean.pgm   # 去噪点/补缝
python3 map_walls.py maps/map_xxx_clean.pgm                    # 覆盖率/连通性/四边墙
python3 map_analyze.py maps/map_xxx_clean.pgm                  # Hough 墙线/双墙检测
```

`map_clean.py` 做三件事（保守，坐标系不变）：

1. 删除 ≤3 格的孤立障碍噪点 → 置为空闲
2. 闭合 1 格缝隙（形态学闭运算）
3. 填充被空闲区包围的 ≤2 格未知小洞

### 6.4 定位流程

```bash
bash ~/clean_all_ros.sh

# 查位姿：看 TF map→base_footprint，或 /amcl_pose（有运动才发布）
```

### 6.5 导航流程


## 8. 工程经验：踩过的坑与解决

### 8.1 激光 TF 朝向 180°（建图漂移的真凶）

**现象**：建图一动就糊/地图呈星芒状，`map→odom` 跳变方向与实际运动相反，未知区 50~58%。

**原因**：`base_to_laser` 的 **yaw 被配成 π**（URDF 与静态 TF 都是 180°），扫描帧相对车身转了 180°；slam 扫描匹配估出的位移与里程计先验**反向**，每帧都要"掰回来"，修正量累计约 2 倍位移。

**诊断**：用 `/scan` 做**扫描-扫描 ICP** 得真实位移（4 s 直行 0.40~0.44 m，与 `/odom` 0.41 m 吻合），再用 `pose_recorder` 同时记 `/odom`、TF、`map→odom`，发现 `map→odom` 修正量 0.71 m 且方向与运动相反。

**修复**：

1. `robot_model.yaml`：`mini_mec.base_to_laser` 第 4 个数 `3.14159…` → `0.0`
2. `mini_mec_robot.urdf`：`laser_joint rpy="0 0 3.14159…"` → `rpy="0 0 0"`
3. 重启后验证：同一段直线 `map→odom` 修正 **0.71 m → 0.011 m**；原地转 57° 后 `map→odom` yaw 变化 **0.00°**

### 8.2 启动模式陷阱（serial/can）

**现象**：TF 测试"获取不到 TF"，`/odom` 无发布者，EKF 无输出。

**原因**：`robot_start.sh` 的 `BASE_MODE` 默认是 `serial`；手工执行时没有传 `can`，于是不启 CAN 桥接 → `/odom` 没数据 → EKF 无输入 → 没有 `odom→base_footprint` TF。

**修复**：脚本默认改为 `BASE_MODE=${BASE_MODE:-can}`（备份 `robot_start.sh.bak_20261115`）。

### 8.3 Zenoh 会话关闭 / slam 丢帧

**现象**：节点日志 `unable to publish message since the zenoh session is closed`；slam 日志 `Message Filter dropping message ... timestamp earlier than all data in the transform cache` / `queue is full`；长时间建图后 `map→odom` 乱跳。

**原因**：

- 路由器重启/抖动会让所有 rmw_zenoh 客户端会话失效（不会自动重连，节点会崩）；
- slam 的消息过滤器队列满后**会持续丢帧**，位姿估计冻结 → 地图错位（"回到发车直道时偏移"就是这个）。

**处理**：

- 别反复重启 zenoh 路由器；确认 `zenoh-router.service` 稳定；
- 长时间建图/导航时**关闭网页摄像头流**，降低 CPU 与 TF 延迟；
- 出现丢帧链后**重启 slam/导航栈**，不要继续建图。

### 8.4 进程/内存堆积

**现象**：多次重启后内存 3.7/3.9 GB、load 48、控制循环掉到 3.6 Hz，导航"卡住不动"。

**原因**：`ros2 launch`/节点没有随脚本退出而清理。

**修复**：`~/clean_all_ros.sh`（按括号模式批量 TERM→KILL，能清 nav2/amcl/map_server/底盘/雷达/IMU 等）；**每次启动前先跑**。

### 8.5 规划路径"画龙"（NavFn 波浪路径）

**现象**：直线目标被规划成明显 S 弯（tortuosity 1.5~2.2）。

**原因**：NavFn 在膨胀代价场里做梯度下降 + 代价地图膨胀过大（radius 0.45 / scaling 4.0）。

**修复**：换 **SmacPlanner2D**（自带平滑），膨胀改 0.35 / scaling 2.0 → tortuosity **1.001**。

### 8.6 车体自遮挡点被当成障碍

**现象**：`/scan_filtered` 里 132 个 0.18~0.19 m 近点（−108° 一带）压在机器人足迹边缘，局部代价地图标成致命障碍。

**修复**：两个代价地图的激光观测加 `obstacle_min_range: 0.30`；也可扩展 `scan_mask` 扇区。

### 8.7 控制器振荡（MPPI 反复打方向）

**现象**：直线行驶时航向在 ±30~40° 反复摆，`cmd_wz` 在 ±0.44 rad/s 来回。

**诊断**（按"规划层/控制层/底盘层/定位层"分层）：

| 层 | 数据 | 结论 |
|---|---|---|
| 规划 | 换 Smac 后 tortuosity 1.001 | 规划层已修好 |
| 控制器 | `cmd_wz` 自己振荡 | **控制器问题** |
| 底盘 | `odom_wz` 与 `cmd_wz` 相关 0.87~0.91 | 底盘正常 |
| 定位 | AMCL yaw 与 TF 差 std 4° | 有抖动但非主因 |

**修复**：MPPI → **DWB + OscillationCritic**。效果：横向偏差 max 0.406→**0.105 m**、航向 std 18°→**10.2°**。

### 8.8 Nav2 启动踩坑清单

| 现象 | 原因 | 修复 |
|---|---|---|
| `name 'false' is not defined` | launch 里 Python 表达式，`use_composition:=false` 小写 | 写 **`False`** |
| `parameter 'height' has invalid type` | 代价地图 width/height 写成浮点 | 用**整数** `4` |
| map_server `yaml-filename parameter is empty` | 自定义参数文件里写了空的 `map_server` 段覆盖了 launch 的 `map:=` | 参数文件**不要写** map_server 段 |
| controller configure 失败 `Controller period more then model dt` | MPPI `controller_frequency` 周期 > `model_dt` | 改 `model_dt: 0.1`（或频率 20） |
| `Timed out while waiting for action server ... compute_path_to_pose` | BT `default_server_timeout` 20 ms 太短（Zenoh） | 改 **3000 ms** |
| 导航到点前反复 `Failed to make progress` | 进度检查器太严 + CPU 过载 | `0.15 m/45 s`；降低 CPU 负载 |
| 插件类名找不到 | Smac 插件名要用 `::` | `nav2_smac_planner::SmacPlanner2D` |

### 8.9 定位与地图的实操经验

1. **扫描匹配是最好的独立验证**：用 `global_localize.py`（似然场 + 粗到细搜索）可以判断"当前扫描能不能对上地图"。得分 >0.5 且与次优拉开 0.1 以上才算可信；若所有候选都在 0.4 上下，说明**车在桌子底下/家具变化处**，先挪车。
2. **AMCL 不会从错误初值自己纠回来**：给 2 m 偏差的初值 + 开一段，仍停在错误区域附近。正确做法：给**大致正确**初值（±0.5 m），或 `/global_localization` 后开一小段。
3. **重定位精度实测**：跟踪 6.4 cm / 3.2°；全局重定位 11.6 cm / 1.6°。
4. **挪车后务必重新给初始位姿**（RViz 2D Pose Estimate 或 `set_initial_pose.py`），否则导航会朝错误方向走。
5. 地图会"过期"：家具被移动后，扫描与地图对不上 → 先重扫地图再做导航/巡检。

### 8.10 其他小坑

| 现象 | 说明 |
|---|---|
| `pkill -f xxx` 把自己 ssh 会话杀了 | `pkill -f` 会匹配到自己的命令行；用 `xxx[y]` 括号写法（如 `rviz_auto_watc[h]`） |
| `ros2 topic echo /scan --field angle_min` 无输出 | Zenoh 下换成完整类型形式 `ros2 topic echo /scan sensor_msgs/msg/LaserScan --once` 或写脚本订阅 |
| 手转车轮测偏航无效 | 电机抱死，编码器读 ~0；必须用**电机驱动**测试（90°/180° 实测轮式比陀螺低约 6% → `yaw_scale=1.06`） |
| heredoc 里带 echo 的 ssh 命令被截断 | 先本地写脚本再 `scp` 执行 |
| 网页 8080 端口被占 | 手动起的实例没退；`pkill` 后重启 `robot-web.service` |

## 10. 故障排查速查表

| 现象 | 优先检查 | 处理 |
|---|---|---|
| 网页/SSH 不通 | 电池电压、是否突然掉电 | 换电池；查 `free -m` 与 `uptime` |
| 没有 `/odom` | 是否 CAN 模式；`can_chassis_bridge` 是否在跑 | `BASE_MODE=can`；看 `/tmp/can_bridge_run.log` |
| 没有 `odom→base` TF | EKF 是否在跑、`/odom` 有没有数据 | 重启 `robot_start.sh` |
| 建图漂移/地图糊 | 激光 TF yaw 是否为 0；`map→odom` 修正是否反向 | 见 8.1 |
| 导航路径呈波浪 | 规划器是否 NavFn；代价地图膨胀 | 换 SmacPlanner2D（见 8.5） |
| 导航反复打方向 | `cmd_wz` 是否振荡 | 用 DWB + Oscillation（见 8.7） |
| 导航"卡住不动" / `Failed to make progress` | CPU load、贴障碍、地图过期 | `clean_all_ros.sh`；放宽进度检查；重扫地图 |
| 定位"跳" / 初始化失败 | 车是否在桌下/家具变化处 | 挪到空地重新 2D Pose Estimate；必要时重扫地图 |
| RViz 打不开/无数据 | 看板日志、Zenoh 中继 | 看 `/tmp/rviz_auto_watch.log`；重启中继 |
| slam 日志大量 dropping | 消息过滤器队列满 | 重启 slam；降低 CPU 负载 |
| `ros2` 命令卡住 | Zenoh CLI 不稳定 | 用 python 脚本订阅代替 |

### 14.1 CAN 命令帧 `0x181`（8 字节）

| 字节 | 内容 | 说明 |
|---|---|---|
| 0–1 | vx（int16 大端，mm/s） | 前后速度 |
| 2–3 | vy（int16 大端，mm/s） | 左右速度 |
| 4–5 | wz（int16 大端，mrad/s） | 旋转角速度 |
| 6–7 | 保留 | 0 |

### 14.3 三种模式对比

| | 建图 | 定位 | 导航 |

### 14.4 名词表

| 术语 | 含义 |
|---|---|
| SLAM | 同步定位与建图 |
| AMCL | 自适应蒙特卡洛定位（粒子滤波） |
| EKF | 扩展卡尔曼滤波（本车用于融合轮速+陀螺） |
| DWB | Nav2 的局部轨迹采样控制器 |

| tortuosity | 路径长度/直线距离，越接近 1 越直 |
| ZUPT | 零速更新（静止时强制速度为零，本车未启用） |
